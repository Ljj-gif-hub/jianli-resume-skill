# 简历写作原则与模板

## 真实性红线（最高优先级）

- 每个技术名词、数量、链接、成就，必须能在当前项目溯源（grep / 文档 / git 复核）
- 项目里没有的，一律不写。尤其警惕"高并发""千万级""分布式事务"这类词，项目没有就绝不出现
- 团队项目只写你本人做的；拿不准的向用户确认
- 量化用真实统计数字；没把握写范围（"9+ 模块"），不编精确数
- 时间线真实（项目周期、在职时间、排障发生时间）
- 交付时提示用户："请逐条核对，面试时简历里每一点都要能讲清楚"

## 通用结构（中文简历）

```markdown
# 简历：<一句话产品名>（<目标岗位>）

【姓名】
电话：【电话】　邮箱：【邮箱】
年龄：【年龄】　现所在地：【城市】
最高学历：【本科/硕士】　意向岗位：<目标岗位>

## 相关技能
（按岗位核心程度排序，3-5 行）

## 项目经历

### <项目名>（<架构一句话>）｜<你的角色>
【<起止时间>】　技术栈：<主技术栈，按岗位排序>
<产品一句话定位：为谁解决什么问题>
- 亮点 bullet × 4-6

## 自我评价
（3-5 句，回扣岗位核心卖点）
```

## 相关技能写法

- 一行一个技术域，括号里给版本/框架：`后端（主力）：Java 17 · Spring Boot 3.2 · Spring MVC · MyBatis Plus`
- 按岗位排序：岗位核心技术在最前、笔墨最多；辅助技术压后，或并入"辅助扩展（AI 方向）"一行
- 用"掌握 / 熟悉 / 有实战"，不用"精通"
- 可以分成：主力技术 / 数据与工程 / 辅助扩展

## 项目经历写法（亮点 bullet）

模板：**<做了什么>**：<怎么做>，<结果 / 规模 / 难点>。

- 动词开头，避免"负责、参与、协助"（显得被动）
- 每个 bullet 优先带一个**真实规模数字**：接口数、模块数、性能提升、成功率、上线地址
- 疑难修复是加分项，写成一段完整叙事：**现象 → 根因 → 方案 → 验证**
- 3-4 个主 bullet + 1-2 个工程化 bullet（测试 / 部署 / 文档）
- 团队项目用"我主导 / 我实现"，不用"我们"

## 自我评价写法

- 写成和项目经历一样的分点：左侧短标签 + 右侧一句话，3 条为宜
- 结构：能独立完成什么闭环 → 特别解决了什么疑难 → 关注什么工程品质 / 到岗能干什么
- 回扣岗位核心卖点（如后端：认证鉴权 / 限流容错 / 部署排障；AI：从 0 到 1 做真 Agent）
- 不说空话，不写「沟通能力强」「学习能力强」这类无证据句

## 版式与渠道

- **附件简历（md + HTML + PDF 三件套，PDF 为标准交付）**：
  - 产出 `resume-<岗位>.html`：优先复用项目内已有 `resume.html` 模板的 CSS 与 `_resume_assets/` 素材（头像/图标），没有则用 skill 内置 `references/resume-template.html`
  - 用 `references/pdf_build.ps1`（Edge 无头模式）转 PDF，输出 `简历-<岗位>.pdf` 与 md 同目录
  - 转完 `Start-Process` 打开 PDF 给用户预览

### 单页优先（硬性要求：恰好一页，不多不少）

简历**必须一页**。JD 模式内容天然偏多，用三道闸保证，按顺序执行、不要跳级：

1. **砍内容（第一道，最优先）**：内容写长后先删弱化项，而不是缩字号
   - 容量上限（一页基准）：技能 ≤5 行 · 项目亮点 4-6 条 · 自我评价 ≤3 条
   - 超了先合并/压缩弱项 bullet（一行压成短语，不重复已写过的技术词），仍超再考虑删次要亮点
2. **选密度档（第二道）**：内容饱满但砍无可砍时，给 `<body>` 加 class 降字号档位：
   - 默认 `font-size:14px` → 内容多改用 `class="tier-compact"`（13px）→ 再多用 `class="tier-dense"`（12px）
   - 这是**可读性的底线**：优先让 PDF 里的字≥12px，不靠肉眼难辨的微缩
3. **自动缩放兜底（第三道）**：模板自带"单页自适应脚本"（见 resume-template.html 底部 `<script>`）：
   - 打印时量出内容真实高度，超出设计画布就整体等比缩小到恰好一页（CSS zoom 会重新布局，不残留空白第二页）
   - **页底留白**：脚本默认保留 60px 底部留白（常量 `BOTTOM`），内容停在留白线之上、不贴页底；想更空/更满改这个常量即可
   - 内容测量取"最后一个内容块的底边"，不是 scrollHeight——避免 min-height 的空底导致内容没超页也被误缩
   - 缩放下限 0.5；若内容多到需要缩到 0.5 以下，说明第一步砍得不够，回头砍内容重出
   - **复用项目 resume.html 时，把这段脚本整段注入到 `</body>` 前**，并确认 `@page` 尺寸与 body 画布一致（内置模板：@page 615.1pt×870pt 对应 body 820×1160）

### HTML/PDF 渲染注意

- 保留模板 `@page`（615.1pt×870pt / A4）、`print-color-adjust: exact`，用系统字体（Microsoft YaHei）保证中文
- 长段落 / bullet 加 `page-break-inside: avoid` 防跨页断裂；单页优先时 row 都会加
- 不依赖 JS 渲染内容；fit 脚本是唯一允许的 JS，且只在打印时缩尺寸，不改内容
- 少用颜文字 / emoji（部分字体打印不显示）
- HTML 里的特殊字符（`& < >`）转义，避免渲染错乱
- 生成后用脚本打出的 **PNG** 看排版（恰好一页、字号清晰）；若仍超页，回到第一道砍内容
- **禁止 Read `.pdf` / `.docx`**：当前火山模型不支持 `content.type=document`，会 400。校验只 `Read` PNG / 看 HTML
- **BOSS 直聘表单**：另产出 ~200 字短版（直接粘贴）+ ~400 字分点长版，突出岗位卖点与出勤/到岗承诺
- 个人信息优先取自 `简历-资料库.md`；资料库没有的一律【占位】，交用户填写并提醒逐条确认

## 事实资料库（简历-资料库.md）

- 项目根目录 `简历-资料库.md` 是**跨岗位共享的事实源**：个人信息、已溯源的项目事实、待确认项
- 生成前先读：占位符优先用它填，缺项才问用户；生成后把本次新确认的事实回写进去
- 含个人敏感信息，靠 .gitignore 的 `*简历*.md` 兜底——禁止提交、禁止进部署包

## 输出纪律

- 文件名：`简历-<岗位>.md`，写入当前项目根目录或用户指定路径
- **面试材料（简历 / 面试准备 / 文案）不提交进公开 Git 仓库**；若项目是公开仓库，提醒用户用 .gitignore 排除或放本地目录
- 生成后给出简短的"亮点提示"：哪些点面试官最可能追问，方便用户提前准备
