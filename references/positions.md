# 岗位定向矩阵

目标：把目标岗位映射到"岗位画像"，按画像定制三件事——①核心卖点（放最前、最醒目）②要挖的证据（去代码里找）③弱化项（压掉篇幅）④措辞（岗位关键词分布）。

## 岗位画像

### 后端开发（Java / Go / Node 等）
- **核心卖点**：业务模块广度、接口与数据层实现、认证鉴权、缓存/限流、事务一致性、部署与线上排障
- **证据清单**：
  - Controller/Service/Repository 数量与业务覆盖（订单/支付/用户/评论/收藏/优惠券...）
  - 安全：JWT/会话、密码散列、越权防护、参数校验、密钥保护
  - 性能与容错：Redis 缓存、注解/脚本限流、异步线程池、消息队列、多级降级
  - 数据库：表设计、索引、事务、多库适配、读写分离
  - 部署：Docker Compose、Nginx、环境变量隔离、监控
  - 疑难：线上 bug 定位（编码、超时、OOM、MQ 死信、退款补偿...）
- **弱化项**：前端动效、UI 细节、AI 提示词设计 → 各压成一行或并入"辅助扩展"
- **措辞**：接口、事务、并发、缓存、限流、鉴权、幂等、降级、可观测性

### 前端开发（Vue / React）
- **核心卖点**：架构设计、组件化、路由/状态管理、性能优化、移动端兼容、交互动效
- **证据清单**：
  - 页面/组件数量、路由懒加载、代码分割、keep-alive 缓存、守卫
  - 状态管理（Pinia/Vuex/Redux）、i18n、主题、SSR/CSR
  - 移动端兼容：rem/viewport、软键盘遮挡、iOS 自动缩放、双滚动条、OOM 修复
  - 性能：骨架屏、图片懒加载/预加载、防抖节流、PWA、内存泄漏排查
  - 第三方集成：地图、播放器、支付 SDK、SSE/WebSocket、多账户隔离
- **弱化项**：后端安全细节、数据库设计
- **措辞**：组件化、状态管理、性能优化、兼容性、动效、工程化

### 全栈开发
- **核心卖点**：端到端交付——从页面到接口到部署的完整闭环
- **证据清单**：前后端实现 + "自己部署上线"的证据；联调、SSE 流式、容器化部署、线上排障
- **措辞**：端到端、全链路、前后端分离、容器化、独立交付

### AI 应用开发 / 大模型应用
- **核心卖点**：Agent 编排、工具调用、RAG、流式输出、多模型适配、降级容错
- **证据清单**：
  - Agent 架构（LangGraph / ReAct / 多智能体 / 并行调研），流水线阶段
  - 自定义工具 / Function Calling、RAG 知识库、MCP
  - SSE 流式推送、任务取消、超时兜底
  - 多供应商 LLM 适配、提示词工程、模型输出结构化/防御式解析
  - 降级容错（LLM/搜索/API 三级降级）、防模型乱输出、配额/失败处理
- **弱化项**：纯 CRUD 业务细节
- **措辞**：Agent、RAG、工具调用、流式、多模型、降级、提示词、可控输出

### 测试开发 / 测试工程师
- **核心卖点**：测试设计、边界与异常用例、自动化、端到端与回归验证
- **证据清单**：
  - 测试文件数与用例类型（单元/接口/E2E/边界/冒烟）
  - 专项验证脚本（上传上限、并发、回归、部署冒烟）
  - 缺陷敏感度：修复过什么 bug、怎么定位、防回归
- **弱化项**：功能数量本身、业务广度
- **措辞**：用例设计、边界条件、回归、自动化、覆盖率、缺陷定位

### RPA / 流程自动化
- **核心卖点**：流程抽象、脚本与工具链、异常处理、执行稳定性、提效
- **证据清单**：自动化脚本、抓取/爬虫、定时任务、工具封装、容错重试、失败恢复
- **措辞**：流程自动化、脚本化、容错、稳定性、提效

### 运维 / DevOps
- **核心卖点**：容器化、CI/CD、监控告警、线上排障、资源与容量优化
- **证据清单**：Docker Compose、Dockerfile、CI 配置、Nginx、监控、故障复盘、OOM/性能调优
- **弱化项**：业务功能细节
- **措辞**：编排、CI/CD、可观测性、故障定位、容量优化、环境隔离

### 算法 / 数据 / 数据分析
- **核心卖点**：数据链路、指标/特征、建模或统计分析能力
- **证据清单**：埋点、数据表设计、统计/分析逻辑、推荐/排序/评分实现、评估方法
- **措辞**：数据链路、指标体系、特征、评估、可解释

### 算法工程师（机器学习 / 深度学习 / LLM 算法）
- **核心卖点**：建模全流程（数据 → 特征 → 训练 → 评估 → 上线）、指标提升有真实数字、工程化落地（推理服务 / 缓存 / 批处理）
- **证据清单**：训练 / 微调脚本与配置、数据预处理管线、评估集与指标（准确率 / 召回 / F1 / AUC）、消融对比、模型压缩 / 推理优化；LLM 方向：LoRA 微调、量化部署、评测集构建
- **弱化项**：纯业务 CRUD、页面细节
- **措辞**：baseline、消融、召回、特征、推理时延、评估集
- **红线**：没有训练 / 评估记录绝不写"提升 X%"，防编造在这里最容易破功

### 数据开发 / 数据工程师
- **核心卖点**：数据链路完整性（采集 → 清洗 → 入库 → 服务）、调度与容错、大表 SQL 优化
- **证据清单**：ETL 脚本与调度（cron / Airflow / DolphinScheduler）、表模型设计（分层 / 宽表）、数据校验与对账、分区 / 索引优化、数据服务接口
- **弱化项**：前端页面、算法细节
- **措辞**：数仓分层、ETL、幂等调度、数据对账、分区裁剪

### 数据分析
- **核心卖点**：指标体系、分析结论驱动真实改动、可视化交付
- **证据清单**：埋点与指标口径、分析脚本（SQL / Python / Excel 进阶）、报表 / 看板、A/B 测试或前后对比、结论落地的产品改动
- **弱化项**：工程实现深度
- **措辞**：指标口径、漏斗、留存、归因、看板、A/B

### 客户端开发（Android / iOS / 鸿蒙 / Flutter）
- **核心卖点**：页面架构与状态管理、性能与包体、崩溃治理、上架与机型兼容
- **证据清单**：工程结构与路由、网络 / 存储层封装、启动 / 滚动 / 内存优化、崩溃与 ANR 排查、签名 / 加固 / 上架记录、机型适配
- **弱化项**：服务端实现细节
- **措辞**：启动优化、内存治理、包体积、崩溃率、机型适配、热更新

### 小程序 / 跨端开发（微信小程序 / uni-app / Taro）
- **核心卖点**：跨端一致性、分包与加载性能、平台审核与发布流
- **证据清单**：分包配置、授权登录 / 支付、分享与订阅消息、平台差异修复、审核与发布记录
- **弱化项**：后端架构
- **措辞**：分包加载、授权链路、平台差异、审核合规

### 嵌入式 / 物联网（MCU / RTOS / 驱动）
- **核心卖点**：软硬件联调、实时性与资源约束、通信协议、运行稳定性
- **证据清单**：MCU / RTOS 工程、串口 / SPI / I2C 驱动、MQTT / Modbus 协议、低功耗与看门狗、OTA 升级
- **弱化项**：Web / 业务系统
- **措辞**：时序、中断、低功耗、OTA、联调、资源占用

### 网络安全 / 安全工程师
- **核心卖点**：漏洞发现与修复闭环、攻防理解、安全开发落地
- **证据清单**：鉴权 / 越权 / 注入防护实现、依赖漏洞升级（CVE）、渗透测试或 CTF 记录、日志审计、密钥管理
- **弱化项**：业务功能广度
- **措辞**：威胁建模、越权、注入、加固、最小权限、CVE

### 游戏开发（Unity / Unreal / Cocos / 游戏服务端）
- **核心卖点**：玩法系统实现、帧率与内存性能、数值与配置管线
- **证据清单**：核心玩法 / 战斗 / 同步实现、资源管理与打包、帧率优化（DrawCall / 对象池）、配置表热更、帧同步 / 状态同步
- **弱化项**：常规 Web 业务
- **措辞**：帧率、DrawCall、对象池、同步、热更新

### 产品经理（技术背景 / 解决方案）
- **核心卖点**：需求 → 方案 → 落地闭环、懂数据与接口、技术可行性判断
- **证据清单**：PRD / 流程图 / 原型、与开发协作痕迹（接口约定 / 联调记录）、埋点与数据验证、上线迭代记录
- **弱化项**：深代码实现细节
- **措辞**：需求拆解、MVP、埋点验证、迭代、技术可行性

### DBA / 数据库工程师
- **核心卖点**：高可用架构、慢查询治理、备份恢复与迁移
- **证据清单**：主从 / 分库分表、索引与执行分析、慢日志治理、备份策略与演练、迁移脚本与回滚
- **弱化项**：业务功能细节
- **措辞**：执行计划、主从延迟、分库分表、备份恢复、慢查询

### 技术支持 / 售前 / 交付工程师
- **核心卖点**：问题定位能力、客户沟通与文档化、部署交付经验
- **证据清单**：部署文档 / 使用手册、故障排查记录、工单 / FAQ 沉淀、演示环境搭建
- **弱化项**：代码实现深度
- **措辞**：交付、部署、排查、文档化、SLA

### 视频剪辑 / 新媒体制作
- **核心卖点**：成片质量与产出效率（模板化流水线）、多平台适配、选题与数据反馈
- **证据清单**：成片与工程文件、剪辑脚本 / 分镜、包装模板与素材资产库、多平台规格适配（竖屏 / 横屏 / 封面）、发布数据与复盘
- **弱化项**：编程技术细节
- **措辞**：分镜、节奏、包装、适配、完播率

### 通用兜底画像（岗位不在上表）
- 先把岗位名拆成技术栈关键词，看能否借用上表近似画像的证据清单（如"音视频开发"借客户端 + 嵌入式画像）
- 不硬套：列出岗位 JD 里的技术关键词 → 在项目里逐项 grep 找证据 → **有证据的写，没有的明确不写**
- 若项目与岗位强相关证据不足，诚实处理（写"熟悉/了解"+ 有学习证明），不要硬凹

## 使用规则

0. **JD 优先级**：用户提供了具体公司 JD 时，整体按 `references/jd-tailoring.md` 定制，本矩阵只用于判断岗位大类、选"1 主 1 辅"画像。JD 硬性要求没有证据的，明确不写。
1. 一个岗位通常命中 **1 个主画像 + 1 个辅助画像**（如 后端+AI、前端+全栈、测试+自动化）
2. 命中后先列证据清单，再逐项 grep 验证，最后才动笔
3. 简历技能栏排序、项目经历 bullet 排序、自我评价、BOSS 文案都按"主画像核心卖点"优先
4. 岗位关键词要自然分布，不要堆砌成术语清单
