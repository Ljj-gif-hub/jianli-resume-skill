# 岗位定向矩阵

目标：把目标岗位映射到"岗位画像"，按画像定制三件事——①核心卖点（放最前、最醒目）②要挖的证据（去代码里找）③弱化项（压掉篇幅）④措辞（岗位关键词分布）。

## 岗位画像

### 后端开发（Java / Go / Node 等）
- **核心卖点**：业务模块广度、接口与数据层实现、认证鉴权、缓存/限流、事务一致性、部署与线上排障
- **证据清单**：
  - Controller/Service/Repository 数量与业务覆盖（订单/支付/用户/评论/收藏/优惠券...）
  - 安全：JWT/会话、密码散列、越权防护、参数校验、密钥保护
  - 性能与容错：Redis 缓存、注解/脚本限流、异步线程池、消息队列、多级降级
  - 数据库：表设计、索引、事务、多库适配、读写分离
  - 部署：Docker Compose、Nginx、环境变量隔离、监控
  - 疑难：线上 bug 定位（编码、超时、OOM、MQ 死信、退款补偿...）
- **弱化项**：前端动效、UI 细节、AI 提示词设计 → 各压成一行或并入"辅助扩展"
- **措辞**：接口、事务、并发、缓存、限流、鉴权、幂等、降级、可观测性

### 前端开发（Vue / React）
- **核心卖点**：架构设计、组件化、路由/状态管理、性能优化、移动端兼容、交互动效
- **证据清单**：
  - 页面/组件数量、路由懒加载、代码分割、keep-alive 缓存、守卫
  - 状态管理（Pinia/Vuex/Redux）、i18n、主题、SSR/CSR
  - 移动端兼容：rem/viewport、软键盘遮挡、iOS 自动缩放、双滚动条、OOM 修复
  - 性能：骨架屏、图片懒加载/预加载、防抖节流、PWA、内存泄漏排查
  - 第三方集成：地图、播放器、支付 SDK、SSE/WebSocket、多账户隔离
- **弱化项**：后端安全细节、数据库设计
- **措辞**：组件化、状态管理、性能优化、兼容性、动效、工程化

### 全栈开发
- **核心卖点**：端到端交付——从页面到接口到部署的完整闭环
- **证据清单**：前后端实现 + "自己部署上线"的证据；联调、SSE 流式、容器化部署、线上排障
- **措辞**：端到端、全链路、前后端分离、容器化、独立交付

### AI 应用开发 / 大模型应用
- **核心卖点**：Agent 编排、工具调用、RAG、流式输出、多模型适配、降级容错
- **证据清单**：
  - Agent 架构（LangGraph / ReAct / 多智能体 / 并行调研），流水线阶段
  - 自定义工具 / Function Calling、RAG 知识库、MCP
  - SSE 流式推送、任务取消、超时兜底
  - 多供应商 LLM 适配、提示词工程、模型输出结构化/防御式解析
  - 降级容错（LLM/搜索/API 三级降级）、防模型乱输出、配额/失败处理
- **弱化项**：纯 CRUD 业务细节
- **措辞**：Agent、RAG、工具调用、流式、多模型、降级、提示词、可控输出

### 测试开发 / 测试工程师
- **核心卖点**：测试设计、边界与异常用例、自动化、端到端与回归验证
- **证据清单**：
  - 测试文件数与用例类型（单元/接口/E2E/边界/冒烟）
  - 专项验证脚本（上传上限、并发、回归、部署冒烟）
  - 缺陷敏感度：修复过什么 bug、怎么定位、防回归
- **弱化项**：功能数量本身、业务广度
- **措辞**：用例设计、边界条件、回归、自动化、覆盖率、缺陷定位

### RPA / 流程自动化
- **核心卖点**：流程抽象、脚本与工具链、异常处理、执行稳定性、提效
- **证据清单**：自动化脚本、抓取/爬虫、定时任务、工具封装、容错重试、失败恢复
- **措辞**：流程自动化、脚本化、容错、稳定性、提效

### 运维 / DevOps
- **核心卖点**：容器化、CI/CD、监控告警、线上排障、资源与容量优化
- **证据清单**：Docker Compose、Dockerfile、CI 配置、Nginx、监控、故障复盘、OOM/性能调优
- **弱化项**：业务功能细节
- **措辞**：编排、CI/CD、可观测性、故障定位、容量优化、环境隔离

### 算法 / 数据 / 数据分析
- **核心卖点**：数据链路、指标/特征、建模或统计分析能力
- **证据清单**：埋点、数据表设计、统计/分析逻辑、推荐/排序/评分实现、评估方法
- **措辞**：数据链路、指标体系、特征、评估、可解释

### 通用兜底画像（岗位不在上表）
- 不套模板：列出岗位 JD 里的技术关键词 → 在项目里逐项 grep 找证据 → **有证据的写，没有的明确不写**
- 若项目与岗位强相关证据不足，诚实处理（写"熟悉/了解"+ 有学习证明），不要硬凹

## 使用规则

0. **JD 优先级**：用户提供了具体公司 JD 时，整体按 `references/jd-tailoring.md` 定制，本矩阵只用于判断岗位大类、选"1 主 1 辅"画像。JD 硬性要求没有证据的，明确不写。
1. 一个岗位通常命中 **1 个主画像 + 1 个辅助画像**（如 后端+AI、前端+全栈、测试+自动化）
2. 命中后先列证据清单，再逐项 grep 验证，最后才动笔
3. 简历技能栏排序、项目经历 bullet 排序、自我评价、BOSS 文案都按"主画像核心卖点"优先
4. 岗位关键词要自然分布，不要堆砌成术语清单
